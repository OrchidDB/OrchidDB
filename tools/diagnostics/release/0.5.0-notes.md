OrchidDB 0.5.0 adds source-first query execution and optional DuckDB completion. Existing language clients remain included.

### Migration notes

- Built-in SpiceDB authorization has been removed, including its secret type, graph policy syntax, session authorization functions and permission-check transport. Existing protected graph definitions are rejected. Migrate enforcement to source authorization or application-owned access hooks before upgrading; deployments still using this integration should remain on 0.4.x until migrated.
- The core Rust library no longer enables DuckDB by default. Enable the `duckdb` feature explicitly for embedded completion; the separately packaged DuckDB extension remains available.
- Trino is a SQL source, not a completion engine. Register it as a source and select `none` or `duckdb` for completion. Intermediate-result uploads to Trino are rejected.

### Execution

- Fully supported queries execute in their sources without a final DuckDB query or DuckDB initialization.
- Engine-independent local scalar UDFs support computed/RAG pipelines. They preserve row count; unsupported relational residuals fail explicitly in `none` mode.
- Source-first APIs accept application-owned SQL/request bindings. Optional DuckDB handles only the relational work assigned to it.
- Existing single-session client APIs remain available. The low-level native ABI remains an integration protocol; this release does not introduce the proposed complete standalone native execution API or remove clients.

### Validation and artifacts

Local integration gates cover DuckDB PostgreSQL/Parquet/Iceberg/Lance/ICU/JSON integrations, host streaming and cancellation, Trino PostgreSQL/Iceberg/cross-catalog queries, OPA filters/masks/denials and outage behavior, and optional DuckDB residual completion. These are fixture-based checks, not production identity-provider, S3 authorization or scale certification.

Packages target macOS ARM64, Linux ARM64 and Linux x86-64. The DuckDB extension targets DuckDB 1.5.6. Native library and client archives retain caller-owned database sessions. See `release-manifest.json` and `SHA256SUMS` for provenance and checksums.

The README is unchanged in this release; the migration notes above supersede its older SpiceDB and engine configuration examples.
